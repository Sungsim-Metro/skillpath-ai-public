Streamlit 화면. 화면 코드만 두고 로직은 다른 폴더의 함수를 호출합니다. (담당: 형섭)

| 파일 | 내용 |
| --- | --- |
| `main.py` | 사이드바 입력과 화면 선택. 첫 화면은 학습 상담이고 나머지는 사이드바 메뉴에서 엽니다. 실행은 저장소 루트에서 `streamlit run app/main.py` |
| `common.py` | 함께 쓰는 상수(색, 문구)와 도우미(`load`, `notice`), 화면에 넘기는 입력 묶음 `Ctx`와 필요한 데이터만 불러오는 `build_ctx` |
| `chat.py` | 학습 상담(첫 화면)과 프로필 로그인 |
| `tabs/saved.py` | 담은 교육과정 화면. 추천 카드의 **담기**로 모은 과정을 봅니다. 로그인하면 프로필에 저장되고 비회원은 이번 접속 동안만 남습니다 |
| `course_card.py` | 추천 과정 카드(순위, 배지, 평점 링크, 추천 이유 접기, 담기). 학습 상담과 학습 추천이 함께 씁니다 |
| `level_radar.py` | 마이페이지의 보유 수준 레이더 차트(영역별 내 단계와 기준 단계) |
| `tour.py` | 처음 들어온 사용자에게 기능을 단계별로 보여 주는 안내 창 |
| `tabs/demand.py` | 시장 수요 |
| `tabs/gap.py` | 부족 역량. 능력 범주별 Gap과 영역별 역량을 펼치고 부족한 기술 표, 교육 공급, 채용 시장 Gap은 접어 둡니다 |
| `tabs/recommend.py` | 학습 추천 |
| `tabs/connect.py` | 현직자에게 물어보기 |
| `tabs/extract.py` | 공고 직접 분석. 메뉴에서 뺐고 파일만 남겼습니다(2026-11-20) |
| `testing.py` | 화면 테스트가 함께 쓰는 `open_app` |
| `test_app.py` | 가짜 모드에서 화면이 오류 없이 뜨는지 확인. `python -m app.test_app` |

새 화면은 `tabs/`에 `render(ctx)` 함수가 있는 파일을 더하고 `main.py`의 `VIEWS`에 한 줄을 넣습니다.
화면을 바로 열려면 주소에 `?view=<값>`을 붙입니다(`chat`, `demand`, `gap`, `recommend`, `saved`, `connect`, `report`). 모르는 값은 학습 상담으로 갑니다.
화면 파일끼리는 서로 가져다 쓰지 않습니다. 함께 쓸 것은 `common.py`에 둡니다.

## 학습 상담 실행

```bash
BEDROCK_MOCK=1 uv run --python 3.11 --with-requirements requirements.txt streamlit run app/main.py
```

접속하면 로그인·회원가입 화면이 나옵니다(`http://localhost:8501`). 닉네임과 비밀번호로 **로그인**하거나 **회원가입**하고, 가입하지 않으려면 **로그인 없이 둘러보기**를 누릅니다. 들어오면 첫 화면이 **학습 상담**입니다. “제가 Docker로 API를 배포했어요” 다음에 “내 경험을 정리해줘”, “무엇이 부족해?”, “그중 어떤 과정을 들을까?”를 차례로 입력하면 각 요청의 결과를 확인할 수 있습니다.

비회원으로 들어온 뒤에도 사이드바에서 닉네임과 비밀번호를 입력하고 **새 프로필 만들기**를 누르면 가입됩니다. 다시 접속하면 같은 정보로 **로그인**합니다. 로그아웃하면 비회원으로 계속 봅니다. 상담에서 “Docker 배포 경험을 프로필에 저장해줘”처럼 저장 대상을 지정할 수 있습니다. 로그인한 회원의 대화는 DynamoDB `skillpath-chat-history`(모의 모드는 로컬 SQLite)에 세션별로 저장되어, 학습 상담 화면 왼쪽 패널의 **최근** 목록에서 다시 볼 수 있습니다(읽기 전용). 이메일·전화번호(+82 국가번호 포함)·주민등록번호·외국인등록번호 모양은 가려서 저장합니다. 화면의 대화는 **로그아웃**하면 비웁니다. 손님은 현재 세션에서 진단과 상담을 이용할 수 있고 대화는 저장되지 않습니다.

목표 직무는 학습 상담 첫 화면의 버튼으로 고르거나 대화로 바꿉니다(고르는 칸은 없습니다). 학습 상담 화면의 **수준 진단 설문**에서는 직무별 세부 능력의 예시를 보고 0~5단계를 선택합니다. 영역마다 단계 표시로 진행을 보여 주고, 일부만 답해도 저장됩니다. 진단 보고서는 사이드바 메뉴의 **진단 보고서** 화면에서 보고 내려받습니다. 목록에 없는 기술은 **기술 수준 직접 입력**에서 이름과 단계를 입력하고 **기술 수준 저장**을 누릅니다. 예를 들어 `OpenTelemetry`를 4단계로 저장한 뒤 같은 이름을 3단계로 다시 저장하면 기존 항목이 갱신됩니다. 로그인하면 프로필에 저장한 단계가 복원됩니다.

클라우드 엔지니어 상담에서 “제가 Docker로 API를 배포했어요”라고 하면 **컨테이너** 문항의 0~5단계 예시가 나옵니다. 전에 답한 문항은 0단계를 포함해 현재 단계가 선택된 채로 다시 열립니다. Docker 수준을 직접 입력한 적이 있다면 컨테이너 응답과 별도로 Docker 단계도 수정할 수 있습니다. 공고와 비교할 때는 Docker에 직접 입력한 단계가 우선합니다.

단계를 고른 뒤 버튼을 누르면 새로 답하거나 바꾼 항목만 반영합니다. 로그인한 사용자는 프로필에 저장하고 손님은 현재 세션에 적용합니다. 질문을 건너뛰거나 화면을 다시 표시하는 것만으로는 프로필을 갱신하지 않습니다. 사용 경험만 있고 수준을 입력하지 않은 기술은 공고와 비교할 때 **수준 미입력**으로 표시하며, 해당 기술의 과정 추천은 수준을 입력할 때까지 보류합니다.

손님으로 먼저 입력한 뒤 로그인했을 때 계정에 저장한 수준이 비어 있으면 **손님 수준을 내 프로필에 저장**을 눌러 이어갈 수 있습니다. 이미 수준을 저장한 계정으로 로그인하면 그 계정의 값을 불러옵니다.

상담에서 “제가 OpenTofu를 사용했어요. OpenTofu만 프로필에 저장해줘”라고 하면 목표 직무를 바꿔도 그 기술이 프로필에 한 번 남습니다. 사전에 없는 이름도 사용할 수 있습니다. 모의 상담에서 한국어 자유 이름을 명확히 지정하려면 “저는 ‘데이터 품질 검사’를 사용했어요”처럼 이름을 따옴표로 감싸세요. 사용 경험만 밝힌 기술은 숙련도를 따로 입력할 때까지 이름만 저장합니다.

상담 화면 위에는 목표 직무, 진단으로 확인한 보유 기술 수, 대화에서 말한 기술 수가 한 줄로 나옵니다. 화면 아래의 추천 질문을 누르면 그 글이 그대로 전송되고, **새 채팅**은 대화만 비웁니다(대화 기록 패널 안에 있고, 패널이 없거나 접혀 있으면 제목 옆에 나옵니다). 부족 역량이나 과정 추천 답 아래의 버튼으로 해당 화면에 가면 **상담으로 돌아가기**가 보입니다. 토큰 수와 세션 ID는 상담 화면에 보여 주지 않고 관리자 화면에서 확인합니다(2026-11-20). 각 질문의 모델 호출, 재시도, 캐시에 없어서 새로 요청한 임베딩 토큰이 해당 대화의 누계에 포함됩니다. 모의 모드에서는 토큰이 0입니다.

관리자는 `/admin?admin=<ADMIN_KEY 값>`(관리자 화면, `app/admin.py`)의 **토큰·비용 → 대화 세션별** 표를 확인할 수 있습니다. 같은 화면에 비교 실험 결과(모델별 평가·비용과 쓸 모델의 결정 기록, 추천 구조 A/B), 데이터 현황, 과정 커버리지, 평가 결과가 있습니다. 값이 없거나 틀리면 `/admin` 주소는 열리지 않습니다. 표는 이 서버의 사용량 로그에 기록된 실제 호출을 집계합니다. 기본 경로는 `outputs/usage/usage.jsonl`입니다. 세션 ID가 없는 예전 기록과 배치 호출은 전체 사용량에 포함됩니다. `USAGE_LOG=off`는 파일 기록을 끄며 현재 대화창의 누계는 계속 표시합니다.

| 모드 | 필요한 설정 |
| --- | --- |
| 모의 (`BEDROCK_MOCK=1`) | AWS 연결 없이 예시 대화를 실행합니다. 입력 검사는 `ai/guardrail.py`의 코드 검사만 합니다. 프로필은 기본적으로 `$XDG_DATA_HOME/skillpath-ai/chat-profiles.sqlite3`에 저장합니다. XDG 경로가 없으면 `~/.local/share`를 사용하며, `SKILLPATH_MOCK_PROFILE_DB`로 파일 위치를 지정할 수 있습니다. |
| 실제 (`BEDROCK_MOCK=0`) | 기존 모델·수요·과정 검색 설정과 함께 입력 가드레일의 `GUARDRAIL_ID`, `GUARDRAIL_VERSION`을 지정합니다(비어 있으면 예전 이름 `BEDROCK_GUARDRAIL_ID`, `BEDROCK_GUARDRAIL_VERSION` 묶음을 읽고, 두 묶음을 섞지 않습니다). 입력 검사는 상담 에이전트와 같은 `ai/guardrail.py`를 씁니다. 런타임 역할에 해당 가드레일의 `bedrock:ApplyGuardrail` 권한이 필요합니다. 입력 점검에 실패한 메시지는 후속 분석에 전달하지 않습니다. |
| 실제 프로필 | `DYNAMODB_PROFILE_TABLE`에 문자열 파티션 키 `nickname`만 있는 테이블을 지정하고 런타임 역할에 해당 테이블의 `dynamodb:GetItem`, `dynamodb:UpdateItem`을 허용합니다. [테이블 준비와 이전 프로필 전환](../backend/README.md) |
| 실제 과정 검색 | `BEDROCK_KB_ID`에 교육과정용 Knowledge Base ID를 지정합니다. 앱의 런타임 역할에는 해당 KB의 `bedrock:Retrieve` 권한이 필요합니다. |
| 비교 실험 | `EXPERIMENT_MODELS`에 모델 ID를 쉼표로 적으면 메시지마다 무작위로 한 모델을 쓰고 답 아래에서 평가를 받습니다. `AB_STRUCTURES`에 추천 구조 이름(`single,reviewed`)을 적으면 과정 추천을 A/B로 보여 주고 선택을 받습니다. 기록은 `DYNAMODB_FEEDBACK_TABLE`(파티션 키 `session_id`, 정렬 키 `turn_id`)에 남고 런타임 역할에 `dynamodb:UpdateItem`, `dynamodb:Scan` 권한이 필요합니다. 내용은 저장하지 않습니다. 셋 다 비우면 꺼집니다. |

색과 글꼴은 저장소 루트의 `.streamlit/config.toml`에서 정합니다. 차트는 Altair로 그립니다.

### 팀장 에이전트 상담 실행

저장소 루트에서 `AB_STRUCTURES=3`으로 실행하면 모든 상담 메시지를 3번 팀장 구조가 처리합니다. 일반 화면과 같은 프로필·수준 진단을 사용합니다. 3번 단독 실행에서는 A/B 투표와 메시지별 무작위 모델 배정이 꺼집니다. 기존 실행 인자 `--supervised`도 같은 구조를 선택하며 환경 설정보다 우선합니다.

```bash
AB_STRUCTURES=3 BEDROCK_MOCK=1 uv run --python 3.11 --with-requirements requirements.txt streamlit run app/main.py
```

“저는 Kubernetes를 배우고 싶어요”에 이어 “그 기술의 교육과정을 보여 주세요”라고 입력하면 앞서 말한 학습 희망을 참조합니다. 실제 모드는 위 표의 실제 상담 설정을 사용합니다. 모의 모드는 로컬 규칙으로 해석하고 검토한 예시 카드를 표시합니다.

1번과 3번의 비교는 아래 명령으로 실행합니다. 1번은 PR #121의 Git 커밋 `8dcf025b16ca7e50dae00fa8a8027432b7dbf462`에서 에이전트·프롬프트·모의 대본을 읽습니다. 새로 복제한 저장소에서 이 객체가 없으면 `git fetch origin pull/121/head`로 받습니다.

```bash
BEDROCK_MOCK=1 uv run --python 3.11 --with-requirements requirements.txt python -m ai.eval.supervised_compare
```

실제 모델과 가드레일 설정이 환경에 있는 터미널에서는 `BEDROCK_MOCK=0`으로 바꾸고 `--bedrock --case wish-reference --max-model-calls 24 --max-guardrail-calls 6`을 붙여 두 턴만 비교합니다. 두 실행 모두 개발 문항, 동일한 예시 수요 및 로컬 과정 검색을 사용하며 각 대화 안에서 문맥을 유지합니다. 실행별 수치와 검사 결과는 `outputs/eval/supervised_compare_*.json`에 생깁니다.
